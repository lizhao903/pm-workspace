## 2026-10-28 开工前的决策

### 开发任务的承载和回写
- **决策**：开发任务导入测试实例（7796，真实库的副本，已带 0013 待验收状态）；进展、产出、提交验收用 `scripts/pmw-task.py` 回写。
- **理由**：用户特意停了 7777，不替用户改回来；本会话和子代理加载的 MCP 指向真实服务，用不了，`pmw-task.py` 直接起 `bin/pmw-mcp-dev` 调同一套工具，负责人、状态、会话标识的处理和 `/task` 一致。
- **撤回**：测试实例的数据随时可以丢；导入脚本按 `dev-key:` 标签去重，切到真实库时重新导入即可。

### CORE-05：0001 到 0004 号迁移没有校验和
- **决策**：不往真实库的迁移记录里补校验和，只在代码里写死这几个文件的期望哈希值，启动时比对，不一致就拒绝启动并说明。
- **理由**：已应用的迁移不能改，补进库里等于改迁移历史。
- **撤回**：去掉代码里的比对即可，库不受影响。

### CORE-06：凭证保险箱的主密钥放哪
- **决策**：macOS 上优先放系统钥匙串（`security` 命令），取不到时退回到数据目录下权限 0600 的密钥文件；测试实例一律用密钥文件，不碰钥匙串。
- **理由**：钥匙串是本机最安全的地方；测试实例和自动化测试不能弹系统授权框。
- **撤回**：两种方式都走同一个接口，换实现不影响数据格式。

### 干系人名字重名
- **决策**：允许重名，靠 id 区分；界面上重名时在名字后面附公司或渠道账号；从 IM 收消息建联系人时，按 IM 身份（渠道 + 编号）认人，不按名字。
- **理由**：真实世界里重名很常见，按名字唯一会把两个人合成一个。
- **撤回**：只影响展示和匹配规则，不改表结构。

### 消息附件存在哪
- **决策**：放在数据目录下的 `attachments/`（和 pm.db 同级），按渠道分子目录。
- **理由**：备份数据目录时附件一起带走；原型里的 `~/Downloads/一人之下/附件` 只是演示用。
- **撤回**：存储路径是配置项，可以改。

### 规格包放哪
- **决策**：`web-next/docs/spec/`，每个模块一个文件。
- **理由**：规格和原型放在一起，用户提需求时打开原型就能找到对应规格。

### TASK-03：定时任务的执行记录
- **决策**：不复用现有的 runs 表，新增定时任务执行记录表（迁移从 0014 起，只加不改）。
- **理由**：现有 runs 是「Claude Code 执行任务」的记录，字段和语义都不同，混用会让开发任务闭环的执行记录变乱。
- **撤回**：新表独立，删掉不影响其他功能。
