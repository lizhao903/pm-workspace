## SPEC-sop-0 模块概述

SOP 是标准工作流：把反复做的事编排成一张有向图（自动步骤、AI 步骤、判断分支、并行、人工检查点），每次按同样的步骤执行，每一步的输入输出都留在执行记录里，人可以在四个地方插手：执行前暂停（逐步确认）、人工检查、人工判断、失败后重试或跳过。给一个人做产品和运营时用，把「客户反馈转需求」「周会纪要整理」「联系人建档」这类事交给流程跑，只在需要人的地方停下。

原型里执行由前端定时器模拟（每 250ms 推一次），每种节点的产出是写死的规则，不连真服务；哪些是模拟、后端要怎么真做，见 `SPEC-sop-12`。

| key | label | color | 条件 |
|---|---|---|---|
| `stopped` | 已终止 | `#a19d92` | `stopped` 为真 |
| `failed` | 失败 | `#c0352b` | 有步骤 `failed` |
| `waiting` | 待我处理 | `#b0570b` | 有步骤 `paused` 或 `review` |

`RunAction`（`web-next/src/sopflow.ts`）：运行页发出的八种动作，`act` 执行。

| `kind` | 额外字段 | 什么时候能做 | 效果 | 日志 |
|---|---|---|---|---|
| `confirm-input` | `step: number; input?: Json` | 步骤 `paused` | 转 `running`，`attempts + 1`；带 `input` 时替换输入并标 `edited: 'input'` | 「输入已确认，开始执行」/「输入已修改，开始执行」 |
| `approve` | `step: number; output?: Json` | 人工检查步骤 `review` | 转 `done`；带 `output` 时替换输出并标 `edited: 'output'`；然后放出下游 | 「检查通过」/「输出已修改并放行」 |
| `route` | `step: number; route: string` | 人工判断步骤 `review` | 转 `done`，`route` 为选中分支，`route_reason = '人工判断'`，标 `edited: 'route'`；没选中的分支下游标 `bypassed` | 「人工判断：走「分支名」」 |
| `rework` | `step: number` | 人工检查步骤 `review`，且有走到的上游 | 这一步回到 `pending`、清掉输出；它的上游（没走到的分支除外）重新 `running`，`attempts + 1`、清掉 `edited`；上游跑完后再回到这一步 | 本步「退回上游重做」，上游「被下游退回，重新执行」 |
| `retry` | `step: number` | 步骤 `failed` | 转 `running`，清掉错误，`attempts + 1` | 「第 N 次尝试」 |
| `skip` | `step: number` | 步骤 `failed`；或 `paused` 且不是分支节点 | 转 `skipped`，输出等于输入，放出下游 | 「已跳过，输入原样传给下游」 |
| `stop` | | 执行没结束 | `stopped = true`，写 `ended_at`；`running`、`paused`、`review` 的步骤回到 `pending` | 「执行被终止」 |
| `step-through` | `on: boolean` | 执行没结束 | 改 `step_through`；只影响之后放出的步骤，已经在跑的不停 | 无 |

### 执行语义

正式产品的执行引擎（SOP-01b）按这里的语义实现，原型 `sopflow.ts` 的 `startRun`、`advance`、`tick`、`act` 是参照。

1. **放行**：一个 `pending` 步骤的依赖全部结束（`done`、`skipped`、`bypassed`）时放出。依赖同一步的几步同时放出，就是并行；依赖多于一步的，等几路都结束才放，就是汇合。一轮放出的步骤可能让下一轮又能放，循环到不动为止。
2. **分支**：步骤有 `branch` 且判断步骤选的不是这个分支，或者它的依赖全是 `bypassed`，标 `bypassed`（日志「所在分支未被选中，不执行」），不执行。
3. **输入**：见 `RunStep.input`。汇合时按上游 key 分组，免得字段互相覆盖。
4. **逐步确认**：`step_through` 为真时，放出的步骤先停在 `paused`（日志「执行前暂停，等待确认输入」），确认后才开始计时。
5. **出结果**：`running` 到 `ms` 后：先判失败（步骤自己的 `fail`，再判类型的 `fail`），失败转 `failed`；分支节点（不是人工判断）算出 `route`，转 `done`（日志「判断结果：走「分支名」，原因」）；人工判断转 `review`（「等待人工判断走哪个分支」）；人工检查转 `review`（「已就绪，等待人工检查」）；其余转 `done`（「完成，用时 N.Ns」）。
6. **判断规则**：示例流程用写死的 `decide`；分类器用类型的 `route`；条件分支有 `rule` 时原型不求值，走第一个分支，原因「按规则「…」判断（原型模拟）」。
7. **结束**：全部步骤结束时写 `ended_at`。被终止的执行不再推进。
8. **快照**：执行带开始时的流程定义，之后改流程不影响它。删除流程后执行记录保留，`sop.name` 照常显示。
9. **失败记运行异常**：步骤每次失败（按「执行 + 步骤 + 次数」只记一次）记一条运行异常，指纹 `sop:<流程 id>:<步骤 key>`，模块 `SOP`，标题「「流程名」步骤名失败」，上下文带 SOP、步骤、执行、输入（见 `SPEC-settings-18`）。演示数据里那次失败不重复记。

### 每种节点的配置项

下表「执行（原型）」是 `run` / `fail` / `route` 的模拟规则；正式产品怎么真做见 `SPEC-sop-12`。耗时是原型 `ms`。

#### 基础

**`auto` 自动执行**（`#3d4fd6`，900ms，说明框「做什么」）：调接口、写数据、发消息这类不需要判断的动作。没有配置项。执行（原型）：输出 = 输入加 `<节点名>_done: true`；示例流程里的自动步骤用写死的 `run`。

**`ai` AI 处理**（`#7a4fd6`，1800ms，说明框「给 AI 的要求」）：生成、提炼、起草、改写。

| 配置项 | key | 控件 | 必填 | 默认 | 选项 / 占位 / 提示 |
|---|---|---|---|---|---|
| 模型 | `model` | select | 否 | `''` | 跟随默认（`''`）/ Claude Opus 5.5 `claude-opus-5-5` / Claude Sonnet 5.5 `claude-sonnet-5-5` / Claude Haiku 5.5 `claude-haiku-5-5`；提示「留空跟随执行这个流程的 Agent 的模型」 |
| 输出字段名 | `output` | text | 否 | `result` | 占位 `result` |

执行（原型）：输出 = 输入加 `<输出字段名>: 「节点名」的生成结果（原型模拟）`。摘要：选了模型时显示模型名。

#### 知识与数据

**`knowledge` 知识检索**（`#2f7d43`，1000ms）：在文档库里按问题找相关段落。

| 配置项 | key | 控件 | 必填 | 默认 | 选项 / 占位 / 提示 |
|---|---|---|---|---|---|
| 检索问题 | `query` | textarea | 是 | | 占位「可以引用输入字段，比如 {{customer}} 的历史需求」；提示「支持 {{字段}}」 |
| 检索范围 | `scope` | multi | 否 | | 文档分类（`CONTENT_CATEGORIES`）；提示「不选就是全部内容」 |
| 最多返回 | `top_k` | number | 否 | `3` | |

执行（原型）：渲染问题，按两个字以上的词在演示文档的标题、正文、标签里数命中次数，取前 `top_k` 条，输出加 `query` 和 `matches: [{ title, score, snippet }]`（片段前 60 字）。摘要「问：…」。

**`extract` 参数提取**（`#0c8599`，1200ms）：从一段文字里抽出指定字段。

| 配置项 | key | 控件 | 必填 | 默认 | 选项 / 占位 / 提示 |
|---|---|---|---|---|---|
| 要提取的字段 | `fields` | text | 是 | | 占位「客户名, 金额, 日期」；提示「逗号隔开」 |
| 从哪个字段里提 | `from` | text | 否 | | 占位「留空自动找最长的那段文字」 |

执行（原型）：按字段名猜正则（金额、日期、电话、邮箱），其余填「（原型模拟：由模型提取）」，输出加 `extracted: { 字段: 值 }`。摘要「提取：…」。

**`template` 模板转换**（`#0c8599`，300ms）：用 `{{字段}}` 把输入拼成一段固定格式的文字。

| 配置项 | key | 控件 | 必填 | 默认 | 选项 / 占位 / 提示 |
|---|---|---|---|---|---|
| 模板 | `template` | code | 是 | | 占位 `{{customer}} 你好，你反馈的「{{demands[0].title}}」已经记录。` |
| 输出字段名 | `output` | text | 否 | `text` | |

执行（原型，真算）：输出 = 输入加 `<输出字段名>: 渲染结果`。摘要是模板本身。

**`aggregate` 变量聚合**（`#0c8599`，200ms）：把几路上游（并行或分支）的输出合成一份。

| 配置项 | key | 控件 | 必填 | 默认 | 选项 / 占位 / 提示 |
|---|---|---|---|---|---|
| 合并方式 | `mode` | select | 否 | `merge` | `merge` 字段合并（后面的覆盖前面的）/ `group` 按上游分组保留 / `first` 取第一个有值的 |

执行（原型，真算）：汇合输入是 `{ 上游 key: 输出 }`；`merge` 按上游顺序合并字段，`group` 原样，`first` 取第一个非空的。摘要「字段合并 / 按上游分组 / 取第一个有值的」。

**`code` 代码执行**（`#495057`，600ms）：写一段代码处理输入。

| 配置项 | key | 控件 | 必填 | 默认 | 选项 / 占位 / 提示 |
|---|---|---|---|---|---|
| 语言 | `language` | select | 否 | `javascript` | `javascript` JavaScript / `python` Python |
| 代码 | `code` | code | 是 | | 占位 `function main(input) {\n  return { total: input.items.length }\n}` |

执行（原型）：不执行，输出加 `code_result: （原型不执行代码，这里是 … 的模拟返回）`。摘要是语言名。

#### 逻辑

**`decide` 条件分支**（`#0f8a8a`，400ms，分支节点）：按规则选分支；规则留空就是人工判断。默认分支「是」`yes`、「否」`no`。没有 `fields`，配置是 `SopStepDef.rule` 和 `cases`（`SPEC-sop-9.11`、`9.12`）。执行（原型）：示例流程用写死的 `decide`；有 `rule` 时不求值、走第一个分支；规则为空时停在 `review` 等人判断。画布底行「规则：…」或「人工判断」。

**`classifier` 问题分类器**（`#0f8a8a`，1200ms，分支节点）：AI 判断输入属于哪一类，每一类一个出口。默认类别「类别 1」`c1`、「类别 2」`c2`。

| 配置项 | key | 控件 | 必填 | 默认 | 选项 / 占位 / 提示 |
|---|---|---|---|---|---|
| 要分类的字段 | `from` | text | 否 | | 占位「留空自动找最长的那段文字」 |
| 分类说明 | `hint` | textarea | 否 | | 占位「每一类的判断依据，比如：提到报错、打不开的算「缺陷」」 |

执行（原型）：取要分类的文字，类别名整个出现在文字里就选它（原因「文字里提到了「类别名」」）；否则类别名不超过 3 个字、其中某个汉字出现在文字里也算命中；都不中归第一类，原因「没有明显命中，归到第一类（原型模拟）」。画布底行「AI 分类」。

**`iterate` 迭代**（`#0f8a8a`，1500ms）：对一个列表里的每一项做同样的事。

| 配置项 | key | 控件 | 必填 | 默认 | 选项 / 占位 / 提示 |
|---|---|---|---|---|---|
| 列表字段 | `list` | text | 是 | | 占位 `demands`；提示「输入里哪个字段是列表」 |
| 每一项做什么 | `action` | textarea | 是 | | 占位「比如：为每条诉求建一条任务」 |
